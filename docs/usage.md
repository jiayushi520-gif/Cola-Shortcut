# 可乐自律管理系统

> 已完成 Apple 签名及 Mac 导入、核心规则和隔离写入实测。iOS 26.1 与 Scriptable 主屏幕扩展尚未实机验证，具体范围见 TEST_REPORT.md。

## 文件与运行方式

- `ColaManager.shortcut`：原生主程序，菜单、额度、打卡、处罚、统计、备份与恢复共用同一份数据。
- `我要喝可乐.shortcut`、`我已经漱口.shortcut`、`我已经刷牙.shortcut`、`查看可乐统计.shortcut`：可以独立启动的原生入口，统一调用 ColaManager，必须同时安装主程序。
- `ColaManager-Test.shortcut`：最小导入测试。
- `ColaManager-Widget.js`：可选的 Scriptable 只读小组件。原生快捷指令不依赖 Scriptable、Python 或持续在线的 Mac。

## iPhone 导入

用 AirDrop 或 iCloud Drive 把 `.shortcut` 文件传到 iPhone，在“文件”App 点开并选择“添加快捷指令”。先导入主程序，再导入四个入口。保留主程序名称 **ColaManager**，入口依赖该名称。

先运行最小测试，确认显示“可乐管理系统运行成功”。再运行 ColaManager，选择“查看本周额度”。首次使用会询问是否初始化；如果另一台设备已有数据，请取消，等待 iCloud 同步，避免把暂时不可见的文件误认为新用户。

本项目开发机为 macOS 15.7.2。没有连接可控制的 iOS 26.1 设备；Mac 导入与运行不能替代 iPhone 验证。

## iCloud 授权

在 iPhone 设置中开启 Apple 账户的 iCloud Drive，并启用快捷指令的 iCloud 同步。首次运行允许快捷指令访问其文件目录；创建刷牙提醒时允许访问提醒事项，并在系统设置中允许提醒事项和快捷指令发送通知。通知实际送达还取决于系统权限。

统一目录为 **iCloud Drive / Shortcuts / ColaManager /**。主状态文件 `state.json` 包含全部饮用记录；`state.backup.json` 是上次写入前备份，`state.pending.json` 是先写入并解析校验的候选文件。

iCloud Drive 提供文件同步，不提供跨设备事务锁。**请一次只在一台设备登记或打卡，等文件同步后再切换设备。** 本程序写入前重新读取并检查变化，但不能保证两台离线设备同时写入时不发生冲突。小组件只读，不参与写入。

## 使用

- **我要喝可乐**：重算本周处罚，检查本周记录，允许时二次确认，确认即扣除本周唯一额度。饮用后提醒清水漱口，并创建刷牙提醒。
- **我已经漱口 / 我已经刷牙**：选择最近48小时内最新饮用记录，显示时间和ID供确认。重复打卡不重复计数；超时刷牙可留痕，但不会撤销处罚。
- **查看本周额度 / 查看统计报告**：按当前设备本地自然周重新计算；周一00:00含起点，下周一00:00不含终点。
- **查看历史记录**：最近4、12、52周或全部，从初始化周开始。
- **设置截止时间**：设置 HH:mm、饮用当天或次日，以及睡前提醒时间。只影响新记录，已登记记录的截止时间不追溯修改。

默认截止为饮用次日02:00，睡前提醒为23:00。应按个人作息首次调整。周日饮用可关联周一凌晨的刷牙。上周记录尚未到期时，不标为违规，但暂缓使用新周额度，待打卡或截止结算，避免新周额度先被消费、随后又触发禁喝。

处罚仅作用于饮用记录所属周的下一自然周，之后恢复一瓶，额度不累计。系统判断的是**是否按时打卡**，不验证实际刷牙行为。无饮用周合规，但不进入漱口/刷牙完成率分母；无样本显示“不适用”。连续合规周数只统计已结束且已结算的周，本周为暂定。

## 原生主屏幕小组件

在快捷指令 App 新建“可乐管理”文件夹，将四个入口放进去。长按主屏幕 → 添加小组件 → 快捷指令 → 选择支持多个快捷指令的尺寸。长按该小组件 → 编辑小组件 → 选择“可乐管理”文件夹。也可放四个小号快捷指令组件，各选择一个入口。

原生快捷指令组件显示操作按钮；动态数值面板由可选的 Scriptable 组件提供。包含确认或文件权限提示的操作可能打开快捷指令 App，这是系统行为。

Apple 说明：https://support.apple.com/en-gb/guide/shortcuts/apd029b36d05/ios

## 自动提醒与每周报告

个人自动化必须在 iPhone 上创建，不能随共享快捷指令文件自动安装。无需手工拼装业务操作，仅选已安装的成品：

1. 快捷指令 → 自动化 → 新建 → 特定时间 → 每周日21:00 → 立即运行 → 选择 **可乐每周报告**。
2. 同样创建每天睡前时间 → 选择 **可乐睡前提醒**。
3. 同样创建每天截止时间之后（默认02:05）→ 选择 **可乐截止检查**。

修改截止时间后，需要同时调整第2、3项的系统触发时间。每次查询或申请饮用也会重算处罚，因此不依赖自动化准点执行。已有数据的查询只读，避免每次看统计都重复写入 iCloud；status 和违规原因会按当前时间重新推导。每周报告保存为目录内的文本报告，并发出通知。系统可能因权限、锁屏或资源限制推迟/阻止执行；请在设备上运行一次确认权限。

## 备份与恢复

菜单“导出备份”选择保存位置，即可导出完整 JSON。恢复前先导出当前状态，再用“恢复备份”选择备份文件，确认替换。恢复会先验证结构和记录日期，再重新计算当前处罚；旧状态保存到 `state.backup.json`。

如果主文件缺失但已有备份，不会自动重置额度。可通过主菜单恢复备份。若快捷指令无法读到 iCloud 文件，先在“文件”App 下载到本机并等待同步。不要用空 JSON 覆盖损坏数据来解除禁喝。

## Scriptable 组件

见 WIDGET_INSTALL.md。必须通过用户授权的文件夹书签访问共享目录；没有授权、读取失败或数据损坏时只显示“数据不可用”。**本机无法验证 iOS 的书签访问和 WidgetKit 行为，不承诺实时刷新或已经通过设备测试。**

## 开发与复现

项目的 `src/` 保留生成器、统一字段定义、只读规则引擎和配置示例；`tests/` 保留结构检查、规则测试、夏令时测试、小组件运行环境模拟测试及原生运行测试。模拟测试数据仅在 work/fixtures 下，不是用户真实记录，也不会被交付小组件读取。

原生工作流采用 Apple 工作流二进制 plist，通过官方 `shortcuts sign --mode anyone` 签名。生成器输入与签名后的成品分开存放。


### 复现命令（Mac 开发机）

```sh
python3 src/build_release.py
python3 src/sign.py
python3 -m unittest discover -s tests -p '*_test.py'
node --test tests/core.test.js tests/widget.test.js
TZ=America/New_York node --test tests/dst.test.js
TZ=Asia/Shanghai node tests/make_fixtures.js
```

原生验收需额外签名并导入 `可乐规则验收`、`可乐最终写入验收`（位于 work 的开发生成物），然后执行：

```sh
python3 src/sign.py 可乐规则验收 可乐最终写入验收
python3 tests/run_native.py
python3 tests/run_mutations.py --reset
```

`--reset` 只备份并重置 `ColaManager-Development/Release` 中的开发数据；不作用于正式目录。开发验收程序跳过确认弹窗与新增提醒事项，核心规则和保存代码与主程序共用。正式程序保留确认操作。

本交付不包含测试饮用数据。开发机上的 `ColaManager-Development`、名称带“开发/验收/测试”的快捷指令，以及标记 `[开发验收]` 的提醒，仅用于本次测试，可自行删除。正式目录已经初始化为空历史，未替你登记实际饮用。
