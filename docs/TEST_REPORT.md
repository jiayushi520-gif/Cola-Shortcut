# 测试报告

测试日期：2026-10-15。开发机：macOS 15.7.2（24G325），Asia/Shanghai；Apple `/usr/bin/shortcuts`、Python 3.14.7、Node 24.19.0。

## 结论

交付的是 Apple 官方工具签名的工作流文件，已经在 Mac 快捷指令 App 导入。核心规则及隔离目录的持久化操作已实际运行通过。**未连接可控制的 iOS 26.1 设备，不能宣称已经通过 iPhone 导入或 Scriptable 主屏幕测试。**

四个中文入口分别可启动，但依赖同时安装的 ColaManager 主程序。这种设计让全部写操作共用同一套逻辑和 iCloud JSON，避免四份独立状态。它们配置为可用于快捷指令组件；iOS 组件选择与点击仍待实机验证。

## 已实际测试通过

### Apple 原生运行时

- 最小签名文件导入并运行，输出“可乐管理系统运行成功”。
- 主程序、四个独立入口、每周报告、截止检查、睡前提醒均成功导入 Mac。
- 原生规则验收：11/11 场景通过，每个场景对照15项定量结果，共165项比较。包括当前额度、处罚、总数、连续合规、完成数和自然周日期。
- 场景：空历史、已饮用、已漱口、截止前待定、下周禁喝、处罚结束恢复、周日跨午夜刷牙、恰好截止时打卡、超时打卡、连续合规、跨年。

- 原生 JSON 保存与读回通过，文件实际保存为 `.json`。
- 独立漱口/刷牙入口在正式空历史下返回没有可关联记录，截止检查入口成功运行；
- 独立统计入口调用主程序成功；正式空历史显示剩余1瓶，完成率“不适用”。正式历史没有测试饮用记录。
- 每周报告入口实际生成 `report-2026-10-12.txt`。
- 提醒事项动作实际创建提醒；修正字段后，在提醒事项 App 核实有明确到期时刻。开发机通知权限关闭，因此没有把“定时通知已经送达”算作通过。
- 损坏 JSON 输入到只读原生验收程序后以非零状态退出，未进入持久化路径。错误信息为无效日期（解析后必填字段缺失），并非友好的 JSON 修复界面。

## 已修复的问题与运行限制

开发中发现并修复了文本变量的序列化格式、空字符串判定、日期差方向、JSON扩展名、不可用的 UUID 动作，以及提醒的到期时间开关。最终记录ID由原生随机列表生成，并检查与已有ID是否碰撞。

已有数据的查询已改为只读，目录创建只在初始化/恢复时执行。最终回归查询耗时6.8秒，查询前后状态字节完全一致。单独文件读取约1.0秒、目录操作约0.3秒；不能仅凭一次耗时将早期延迟归因于某个动作。

最后一轮曾有一个 iCloud 读取/写入相关运行超过180秒；串行复测通过，报告随后生成。未取得足以确定根因的系统诊断，因此保留为**间歇性文件提供程序/运行时等待风险**。不能承诺每次操作瞬时完成；若无结果应先检查文件与同步状态，不要并发重复登记。

iCloud 不是事务数据库。写前比较不能防住两台设备同时离线写入；应保持一次只在一台设备写入。系统保存的是打卡声明，无法核实是否实际刷牙。

## iPhone 最小验收步骤

1. 导入并运行 ColaManager-Test，确认成功文字。
2. 先导入 ColaManager，再导入四入口。打开统计入口，允许文件访问；核对初始化或已同步的真实历史。
3. 把四入口放进快捷指令小组件；点击统计，确认可启动并显示相同数据。
4. 仅在实际饮用时登记，马上尝试第二次确认被拦截；完成漱口及刷牙打卡后检查时间和ID。查看提醒事项是否有睡前到期时间，并允许通知。
5. 按 WIDGET_INSTALL.md 授权书签。先在 Scriptable App 预览，再在小/中号主屏幕组件核对。读取失败时停留在“数据不可用”，不要手填模拟数字。
6. 用真实备份验证导出/恢复，并设置三个时间自动化。组件刷新由系统调度；即时状态以主程序报告为准。

开发证据位于交付包 `evidence/`，最终文件哈希位于 `SHA256SUMS.json`。
